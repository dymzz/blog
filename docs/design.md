# 个人网站中文化 + 静态可用性 + SEO 基础检查

## 1. 文档目标

本文档用于冻结个人网站的中文化默认约束、静态模式可用性基线，以及 SEO 基础检查项，作为后续页面开发、组件接入、样式调整与发布验收的统一依据。

本文档适用于：

- 首页
- 博客列表页
- 文章详情页
- 标签页
- 归档页
- 关于页
- 项目页
- 其他公共内容页

---

## 2. 总体冻结原则

### 2.1 默认语言原则

全站默认可见文案使用中文。

除明确标注的第三方嵌入内容、代码示例、外文引用外，页面主标题、副标题、导航文案、按钮文案、空状态文案、分页文案、页脚文案、错误提示文案均应优先使用中文。

### 2.2 页面语言标记原则

全站根 HTML 语言标记固定为：

```html
<html lang="zh-CN">
```

该规则适用于所有公共页面，不得遗漏，不得默认依赖运行时补写。

### 2.3 静态模式原则

网站默认按静态模式构建与部署。

核心内容访问链路必须在静态产物下直接可用，不依赖客户端 JavaScript 才能完成基础阅读、页面跳转与页面索引访问。

### 2.4 渐进增强原则

交互能力分为两类：

1. 核心交互：无 JavaScript 时也必须可用。
2. 增强交互：允许在启用 JavaScript 后增强体验，但失效时不得阻断主流程。

---

## 3. 中文化基线要求

### 3.1 可见文案默认中文

以下内容默认使用中文：

- 站点标题
- 站点副标题
- 导航菜单
- 首页介绍文案
- 博客页标题与说明
- 标签页标题与说明
- 归档页标题与说明
- 项目页标题与说明
- 关于页标题与说明
- 分页按钮文案
- 空状态提示
- 404 页面文案
- 页脚说明
- 版权说明
- 搜索提示文案
- 评论区提示文案

### 3.2 可保留原文的内容边界

以下内容允许保留原文，不强制翻译：

- 代码片段
- API 路径
- 技术名词中已广泛固定的英文表达
- 引用的原始外文标题
- 第三方服务名称
- 文章中明确说明为英文原文的段落

### 3.3 中文化一致性要求

中文文案需保持一致，不得同一站点内同时混用以下表达而无规则：

- “Blog” 与 “博客”
- “Archive” 与 “归档”
- “Projects” 与 “项目”
- “About” 与 “关于”
- “Read more” 与 “阅读更多”

若保留英文品牌词，应采用“品牌名 + 中文说明”的形式，而不是整页混杂英文 UI 文案。

## 4. 页面语言与 Head 输出要求

### 4.1 HTML 语言标记

所有页面最终输出的 HTML 根节点必须显式包含：

```html
<html lang="zh-CN">
```

不得仅在开发环境可见，也不得仅依赖客户端脚本后补。

### 4.2 页面标题要求

所有公共页面必须输出有效的 `<title>`，且标题默认中文化。

推荐格式：

```text
页面标题 - 站点名称
```

示例：

- 首页：个人网站首页 - 站点名称
- 博客：博客 - 站点名称
- 关于：关于 - 站点名称
- 项目：项目 - 站点名称
- 文章页：文章标题 - 站点名称

### 4.3 页面描述要求

首页与博客列表页必须输出中文 `description`。

文章详情页应优先使用文章摘要、简介或前言生成 `description`，不得为空。

标签页、归档页、项目页、关于页建议输出对应的中文描述。

### 4.4 禁止项

禁止出现以下情况：

- 页面无 `<title>`
- 页面 title 仍为脚手架默认值
- 页面 description 为空
- 页面 description 使用明显占位文本
- 页面语言标记缺失
- 页面语言标记与实际页面主语言不一致

---

## 5. 静态可用性基线

## 5.1 核心可用页面

在静态构建产物中，以下页面必须直接可访问：

- 首页
- 博客列表页
- 文章详情页
- 标签页
- 归档页
- 关于页
- 项目页
- 404 页面

### 5.2 无 JavaScript 下必须可用的核心能力

在禁用 JavaScript 或脚本加载失败的情况下，以下能力仍必须成立：

- 可打开首页
- 可打开博客列表页
- 可进入文章详情页
- 可通过导航访问其他公共页面
- 可通过标签或归档页浏览文章
- 可使用上一页 / 下一页完成基础分页跳转
- 可阅读页面主体内容
- 可通过目录锚点跳转到文章内部章节（若页面提供目录）

### 5.3 可降级的增强能力

以下能力允许依赖 JavaScript 增强，但失效时不得阻断主链路：

- 站内搜索
- 评论加载
- 深色模式状态记忆
- 动画效果
- 返回顶部按钮
- 代码块复制按钮
- 客户端过滤与排序增强

### 5.4 不可接受的情况

以下情况视为不满足静态可用性要求：

- 页面主体内容需等待客户端请求后才能出现
- 页面导航依赖 JavaScript 才能展开基础入口
- 文章链接存在但静态产物未生成对应页面
- 标签页或归档页无法在静态模式下打开
- 文章列表只能通过客户端渲染获取
- 页面只显示加载中状态，且无静态回退内容

## 6. 响应式检查基线

### 6.1 检查目标

网站在常见桌面端与移动端宽度下应保证：

- 页面主内容可阅读
- 导航可访问
- 标题不严重溢出
- 图片不超出容器
- 代码块可滚动或正确换行处理
- 分页按钮可点击
- 卡片列表不出现严重重叠

### 6.2 最小检查断点

至少检查以下宽度：

- 360px
- 390px
- 768px
- 1024px
- 1280px

### 6.3 重点检查页面

优先检查：

- 首页
- 博客列表页
- 文章详情页
- 标签页
- 项目页
- 404 页面

### 6.4 不可接受的情况

- 首屏主要按钮超出屏幕
- 页面出现横向滚动且非代码块、非表格导致
- 菜单被遮挡且无法进入
- 文章目录遮挡正文
- 图片或卡片布局断裂
- 页脚重叠或文本裁切

---

## 7. 交互检查基线

### 7.1 核心交互检查

以下交互必须在静态模式下可用：

- 顶部导航跳转
- 博客列表进入文章页
- 标签跳转
- 归档跳转
- 上一篇 / 下一篇跳转
- 页内锚点跳转
- 分页跳转

### 7.2 增强交互检查

以下交互为增强项，检查目标是“存在时可用，失效时不影响主流程”：

- 搜索框输入与结果展示
- 评论区加载
- 深色模式切换
- 动效触发
- 代码复制按钮

### 7.3 交互检查验收口径

若增强交互异常，但页面内容浏览、链接跳转、文章阅读、归档访问均正常，则判定为“增强项问题”，不直接判定为静态主链路失败。

若基础阅读与页面跳转受阻，则判定为“核心链路失败”，必须优先修复。

## 8. SEO 基础检查要求

### 8.1 首页检查项

首页至少满足：

- `html lang="zh-CN"`
- 存在中文 `<title>`
- 存在中文 `<meta name="description">`
- 页面主要可见内容为中文

### 8.2 博客列表页检查项

博客列表页至少满足：

- `html lang="zh-CN"`
- 存在中文 `<title>`
- 存在中文 `<meta name="description">`
- 页面标题与列表说明为中文

### 8.3 文章详情页检查项

文章详情页至少满足：

- `html lang="zh-CN"`
- `<title>` 中包含文章标题
- description 有值
- 页面主体内容在静态源码中可见

### 8.4 通用检查项

所有公共页面建议进一步满足：

- 具备唯一 title
- 具备合理 description
- Head 输出不是默认模板残留
- Open Graph 标题与描述与页面主信息一致
- 页面链接结构清晰稳定

### 8.5 基础 SEO 失败判定

出现以下情况，视为未通过基础 SEO 检查：

- 首页无中文 title
- 首页无中文 description
- 博客页无中文 title
- 博客页无中文 description
- HTML 语言标记缺失
- HTML 语言标记错误
- 页面标题仍为默认模板占位值
- 页面描述为空或无意义占位文案

---

## 9. 推荐实现方式

### 9.1 全站语言统一出口

在全站基础布局层统一输出：

- `<html lang="zh-CN">`
- 通用 head
- 统一 title 拼装规则
- 统一 description 默认回退规则

### 9.2 页面元信息统一管理

建议在统一 SEO 组件或布局层管理：

- title
- description
- canonical
- Open Graph title
- Open Graph description

首页、博客页使用明确中文常量；文章页从 frontmatter 读取标题与摘要。

### 9.3 内容侧约束

建议文章 frontmatter 至少包含：

- `title`
- `description` 或 `summary`
- `pubDate`
- `updatedDate`
- `tags`
- `draft`

若缺少摘要字段，应在构建阶段提供明确回退逻辑，而不是输出空 description。

- [ ] 全站主 UI 文案默认中文

- [ ] 博客列表页文案为中文

- [ ] 分页、空状态、错误提示默认中文

### 10.2 语言标记验收

- [ ] 所有公共页面输出 `html lang="zh-CN"`
- [ ] 页面主内容语言与语言标记一致

### 10.3 静态可用性验收

- [ ] 禁用 JavaScript 后首页仍可访问
- [ ] 禁用 JavaScript 后博客列表页仍可访问
- [ ] 禁用 JavaScript 后文章详情页仍可访问
- [ ] 禁用 JavaScript 后导航跳转仍成立
- [ ] 标签页与归档页在静态模式下可访问

### 10.4 响应式验收

- [ ] 360px 下首页可读
- [ ] 390px 下博客页可读
- [ ] 768px 下文章页布局正常
- [ ] 1024px 下目录与正文不冲突
- [ ] 1280px 下整体布局无异常留白或断裂

### 10.5 SEO 基础验收

- [ ] 首页存在中文 title
- [ ] 首页存在中文 description
- [ ] 博客页存在中文 title
- [ ] 博客页存在中文 description
- [ ] 文章页 title 与文章标题一致
- [ ] 页面无默认占位标题
- [ ] 页面无空 description

---

## 11. 最小结论

个人网站若以中文内容发布为默认形态，则“中文化 + 静态可用性 + SEO 基础检查”不应作为上线后的补丁项，而应作为最初的工程基线。

后续所有页面、组件与交互接入，均应遵守以下优先顺序：

1. 先保证中文默认输出。
2. 先保证静态模式可用。
3. 再增加客户端增强交互。
4. 最后补充视觉与体验优化。

该顺序不得颠倒。
